THIS CYCLE

What's New in OBT3

AUDIO

Tail-audio loss — fixed

Stop no longer discards buffered sound: the muxer now drains the audio queue fully before closing the pipe. The last seconds of your recording keep their sound.

AUDIO

One hardware clock

WASAPI packets carry real QPC device positions and audio is armed on the same common T0 as video — A/V offset measured at 0.000s across cold and warm sessions.

CAPTURE

Video-only path — fixed

Recording with audio disabled used to abort at the first frame (orphan audio input). Now it's a first-class mode: clean single-stream MP4, no output surprises.

TRUTH

Honest pass reporting

The session result now counts every dropped byte at the mux layer. If a file is missing captured audio, the recorder says so instead of reporting success.

HARDWARE

Intel QSV joins the FFmpeg path

CFR pacing and preset mapping for h264_qsv (hwmap derive_device=qsv) — validated on Intel hardware. NVIDIA NVENC remains the native production encoder.

UX

Overlay truthfulness

Hub offline is now explicit — the overlay shows a clear offline state instead of a fake "Recording". The launcher no longer rewrites your config every second.

LOG

Engineering Highlights

MUXDrain-until-empty stop — LiveMux waits for the queue to actually empty before pipe EOF (bounded by timeout).
AUDITMuxDroppedBytes surfaced into SessionResult.Pass — sidecar accounting can no longer mask mux-side loss.
QPCUnit alignment for WASAPI positions + video T0 anchored at Output#0 — one clock, no steering.
QSVCFR + preset mapping completed for the FFmpeg engine; vbv triplet dropped in favor of stable CBR.
CFGUseOverlayEnabled write race resolved — config.json is the single source of truth; launcher writes only on user toggle.
