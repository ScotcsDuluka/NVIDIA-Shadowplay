Modern capture APIs + hardware encoder status

Encoder Support

NVIDIA NVENC

Ready

Native in-app GPU encoding (production path): H.264 CBR/CFR, zero-copy D3D11 texture submission, proven stable in long-run stress tests.

Intel QSV

Partial

Intel QuickSync available through the FFmpeg engine path (hwmap derive_device=qsv) — validated on Intel hardware, experimental.

AMD AMF

Soon

AMD Advanced Media Framework encoder on roadmap.


API Capture

Windows.Graphics.Capture

Partial

Modern Windows 10/11 API via the FFmpeg engine (gfxcapture). Native overlay path still uses Desktop Duplication — WGC slot in the overlay menu is coming.

Desktop Duplication API

Recommended

The production capture path (native engine, zero-copy D3D11). Minimal latency, captures exclusive fullscreen (with limitations).

GDI Screen Grabber

Partial

Legacy fallback via the FFmpeg engine (gdigrab). CPU heavy — use only when needed.

CAUTION

Known Limitations

  • DRM Content : Netflix/Disney+ blocked by Windows protection
  • Fullscreen : Exclusive mode not supported (no-hook design)
  • Solution : Use Borderless Windowed mode in games
TIP

Performance Optimization

For best results, use NVIDIA hardware encoders (e.g., h264_nvenc) via FFmpeg at 1920 × 1080 resolution. This ensures minimal CPU usage and maximum recording quality.

Deep Dive

Modular Architecture

Each module with distinct border color — real stack components

API/

Screen capture abstraction: Windows.Graphics.Capture, Desktop Duplication, GDI fallback. Provides unified interface for frame grabbing.

App Experience/

User settings, hotkey manager, UI state, theming, and configuration persistence. Responsive design and smooth animations.

Engine/

FFmpeg encoding pipeline, replay buffer management, hardware acceleration dispatcher, and recording session controller.

Notifier/

System tray integration, toast notifications, error reporting, status updates, and user alerts for recording events.

Overlay/
