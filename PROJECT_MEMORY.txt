[PHASE 1 — VIDEO PIPELINE]

เป้าหมาย:
Engine เดียวรองรับ capture backend อย่างน้อย:

- ddagrab
- gfxcapture

หลัก:
- Backend ต้องแยกจาก Encoder
- Encoder ห้ามรู้ implementation ของ backend
- Output ห้าม consume raw VideoFrame
- VideoLayer รับผิดชอบ bounded handoff / queue policy
- Backend ไม่เป็นเจ้าของ queue policy
- Audio ยังไม่รวมใน Phase นี้
- UI ยังไม่รวมใน Phase นี้

[VIDEO FRAME CONTRACT]

Concept:
- IVideoFrame = frame จริงเท่านั้น
- ไม่ใช้ fake frame เพื่อแทน dropped frame

Frame acquisition semantic:
- FrameAvailable
- NoFrame
- Error

Dropped frame:
- ไม่ส่งเป็น downstream frame
- เก็บผ่าน diagnostics/metrics

Frame contract ต้องพิจารณา:
- Origin CPU/GPU
- PixelFormat
- Dimensions
- Timestamp
- Ownership
- Lifetime
- GPU resource semantics


[THREADING / HANDOFF]

หลัก:
- Capture backend ต้องไม่ block encoder แบบไม่จำกัดเวลา
- Handoff ต้อง bounded
- ห้าม unlimited queue
- Queue/backpressure policy เป็นความรับผิดชอบของ VideoLayer/Handoff
- Backend ห้ามอ่านหรือควบคุม queue policy

Current design direction:
- Bounded queue
- Default policy: DropOldest / DropNewest
- ยังไม่ล็อก magic timeout เช่น 5 ms
- หลีกเลี่ยง synchronous callback ที่สามารถ block capture


[TIMESTAMP MODEL]

หลัก:
- Engine ใช้ QPC-based monotonic time เป็น reference clock
- WGC SystemRelativeTime เป็น QPC-based time
- WGC property ถูก expose เป็น TimeSpan
- TimeSpan.Ticks = 100 ns units
- Stopwatch.GetTimestamp() = raw QPC counter ticks
- TimeSpan.Ticks และ Stopwatch.GetTimestamp() ห้ามนำมาลบกันตรง ๆ
- ต้อง normalize ให้เป็น internal Engine PTS unit เดียว
- ต้อง document conversion formula

V2:
- Source clock: QPC
- Exact normalization: ต้องกำหนด/verify ก่อน production implementation

A/V ในอนาคต:
- Video และ Audio ควรใช้ QPC clock domain เดียวกัน
- ห้ามใช้ DateTime clock สำหรับ media synchronization
